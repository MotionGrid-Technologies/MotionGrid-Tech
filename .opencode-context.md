# OpenCode Context Guide — MotionGrid Technologies Website

## Overview
This document provides context for OpenCode to help generate consistent, reusable code for the MotionGrid Technologies marketing site and admin portal.

## Project Status

**Current Phase:** Pre-launch MVP (August 2026)

MotionGrid Technologies is a South African bespoke software development studio. This site markets the company, lists its technology stack and industries, and provides a gated admin area for demo requests and (future) product analytics.

**Completed Features:**
- Public marketing pages: Home, About, Products, Technology (+ frontend/backend/other sub-pages), Industries, Contact, Sandbox, Tools
- Trust/legal pages: Security, Accessibility, Privacy, Terms, Cookies
- Design system: obsidian + brushed chrome + signal-orange (`#f2761d`), "Filament" motif
- Admin section at `/adminj2-v1/*`: login, dashboard, autofield, seo, stats
- Custom session-based admin auth (`lib/admin-auth.ts`) with HMAC-signed cookies
- `proxy.ts` gates all `/adminj2-v1/*` routes except login
- SQLite store (`lib/db.ts`) for demo requests and PayFast payment rows
- Security headers in `next.config.ts` (HSTS, X-Frame-Options, etc.)
- PostHog analytics scaffold (inert until key is set)
- Responsive layout, keyboard focus visible, reduced-motion respected

## Reusability & Component Architecture

**Core principle: everything should be built as a reusable component or widget.**

- **Atomic UI components** live in `components/ui/`. They should accept props for variant, size, state, and className overrides. Examples: `Button`, `Card`, `SectionHeading`, `StatusPill`, `TechBadge`, `ContactLine`, `Eyebrow`, `Container`.
- **Section widgets** live in `components/sections/`. They should be page-agnostic building blocks that accept data via props. Examples: `PageHero`, `LegalDoc`, `CodePlayground`.
- **Motif components** live in `components/motifs/` and provide the signature "Filament" graphic device. Use them across pages rather than duplicating SVG or decorative markup.
- **Navigation components** live in `components/nav/`. The `Navbar` and `Footer` are driven by `navItems` and `footerColumns` from `lib/site.ts` so adding/removing links does not require editing components.
- **Data-driven pages:** Public pages should consume arrays from `lib/site.ts` and `lib/technologies.ts`. Avoid hardcoding lists of industries, technologies, or founders inside page components.
- **New feature rule:** When adding a new page section, ask "can this become a widget?" If the same visual pattern could appear on two pages, extract it into `components/sections/` or `components/ui/`.
- **Composability:** Prefer composing smaller components over copying large JSX blocks. Use `children`, render props, or configuration objects to keep page files thin.
- **Type safety:** Define TypeScript props interfaces for every new component. Reuse existing types from `lib/site.ts`, `lib/technologies.ts`, and `lib/db.ts` where possible.

## Database — CRITICAL NOTES

SQLite via `better-sqlite3`. The native addon is kept server-only via `serverExternalPackages` in `next.config.ts`.

Tables:
- `demo_requests` — name, company, email, phone, message, status (`new | contacted | archived`)
- `payfast_payments` — payment metadata rows (read-only until ITN webhook is wired)

## CSS / Tailwind Conventions

1. Use Tailwind v4 CSS-first tokens from `app/globals.css`
2. Use semantic classes: `text-chrome-100`, `bg-obsidian`, `border-hairline`, `text-signal`
3. Use `.mg-brushed`, `.mg-chrome-text`, `.mg-eyebrow` utilities where appropriate
4. Mobile-first responsive design
5. Respect `prefers-reduced-motion`
6. Keep focus rings visible (`:focus-visible` uses signal orange)
