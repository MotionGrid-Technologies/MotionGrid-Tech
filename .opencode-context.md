# OpenCode Context Guide — MotionGrid Technologies Website

## Overview
MotionGrid Technologies is a South African bespoke software development studio. This repo is the **MotionGrid marketing site + admin dashboard** — MotionGrid-only. The former AutoField (workshop SaaS) admin backdoor has been removed and its schema/migrations archived under `archive/`.

---

## Project Status

**Current Phase:** Pre-launch MVP (2026)

**Completed Features:**
- Public marketing pages: Home, About, Products, Technology (+ frontend/backend/other sub-pages), Industries, Blog, Contact, Sandbox, Tools
- Legal pages: Privacy, Terms, Cookies
- Design system: obsidian + brushed chrome + signal-orange (`#f2761d`), "Filament" motif
- Admin section at `/dashboard/admin/*`: demo requests dashboard, SEO scorer, stats, blog, marketing emails
- Auth: Supabase Auth against the **MotionGrid** project (`SITE_SUPABASE_*`) with a Custom Access Token Hook that injects `app_metadata.role` from `public.profiles.role` (roles: `user`, `admin`, `super_admin`)
- `proxy.ts` gates `/dashboard/*` routes using the MotionGrid session
- Supabase lead store (`lib/lead-store.ts`) for demo requests + PayFast payments
- Marketing email store + Tiptap editor (`lib/marketing-emails-store.ts`, `lib/marketing-email.ts`)
- Blog engine (`lib/blog-store.ts`) — DB-driven posts, categories, authors, view tracking
- PostHog analytics scaffold, cookie consent
- Responsive layout, keyboard focus visible, reduced-motion respected

## Database — CRITICAL NOTES

MotionGrid-only. One Supabase project (`SITE_SUPABASE_*` / `NEXT_PUBLIC_SITE_SUPABASE_*`).

Tables (all RLS-enabled, service-role only unless noted):
- `profiles` — `id` (FK `auth.users`), `full_name`, `role` (`user|admin|super_admin`), `created_at`, `updated_at`
- `demo_requests` — contact form leads
- `payfast_payments` — payment metadata (read-only until ITN webhook wired)
- `marketing_emails` — Tiptap email drafts
- `email_logs` — email delivery audit
- `blog_authors`, `blog_categories`, `blog_posts`, `blog_post_categories`, `blog_views`
- `rate_limit_counters` — fixed-window counters + `check_rate_limit()` RPC

Service-role access is server-only (Server Components / Server Actions / API routes).

## Admin Auth — CRITICAL NOTES

- Login at `/login` authenticates against the MotionGrid Supabase project via `lib/siteSupabaseServer.ts`.
- The **Custom Access Token Hook** (`public.custom_access_token_hook`) reads `profiles.role` and injects `app_metadata.role` into the JWT. It is enabled in the MotionGrid Auth dashboard.
- `getRoleFromJWT` (`lib/role.ts`) reads `app_metadata.role`; returns `admin|super_admin` or `client` (unknown → treated as non-admin).
- `/dashboard/admin/*` requires `admin` or `super_admin`. `proxy.ts` guards routes; `app/dashboard/admin/layout.tsx` re-checks server-side.
- Navbar shows **Sign In** when logged out, **profile icon → /dashboard + Log out** when logged in.

## CSS / Tailwind Conventions

1. Use Tailwind v4 CSS-first tokens from `app/globals.css`
2. Use semantic classes: `text-chrome-100`, `bg-obsidian`, `border-hairline`, `text-signal`
3. Use `.mg-brushed`, `.mg-chrome-text`, `.mg-eyebrow` utilities where appropriate
4. Mobile-first responsive design
5. Respect `prefers-reduced-motion`
6. Keep focus rings visible (`:focus-visible` uses signal orange)

## Security & Performance

- Security headers applied globally in `next.config.ts`
- Supabase service-role access is server-only
- Admin routes protected by `proxy.ts` + layout checks
- Rate limiting via `check_rate_limit` RPC (login, forms, API)
- Turnstile on public forms + login
- PostHog gated behind cookie consent
